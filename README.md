# VibeHunt · Входное тестирование 5.0

Готовый статический MVP для GitHub Pages. Открывается на телефоне и компьютере. Никаких серверов, баз данных, сборщиков и обязательных регистраций нет.

## Что реализовано

- Экран приветствия с оформлением VibeHunt.
- Три поля короткого свободного ответа — **без таймера**. Любое поле можно пропустить: знакомство не блокирует основной тест.
- После нажатия кнопки «Начать тест» запускается **таймер 05:00**.
- 23 задания: 10 выборов одного из двух, 5 шкал 1–5, 3 выбора двух качеств, 2 выбора двух зелёных/красных флагов и 3 выбора одного флага.
- Кнопки «Назад» и «Далее», индикатор прогресса, проверка количества выбранных ответов.
- После окончания пяти минут тест не сбрасывает данные: пользователь может спокойно завершить прохождение. Это добровольный ограничитель времени, а не наказание.
- Подсчёт по утверждённой матрице VibeHunt 5.0, 15 персонажей, экран суперсил и мотивационных условий.
- Если результаты нескольких профилей близки, пользователь выбирает оформление карточки среди подходящих Вайбо. Исходный расчёт не изменяется.
- Локальный отклик «Это я / Частично / Не совсем», возможность поделиться текстом результата или пройти снова.
- Черновой экран следующего шага. **Большое тестирование пока не подключено.**

## Как разместить на GitHub Pages

1. Создайте на GitHub **новый публичный репозиторий** (например, `vibehunt-mvp`).
2. Загрузите в его **корень** все файлы этой папки, включая `index.html`, `styles.css`, `app.mjs`, `content.mjs`, `scoring.mjs`, `favicon.svg`, `.nojekyll`. Файлы `README.md` и `test.mjs` могут лежать там же.
3. Откройте **Settings → Pages → Build and deployment**.
4. В **Source** выберите **Deploy from a branch**, в **Branch** — `main` и папку `/ (root)`. Нажмите **Save**.
5. Через некоторое время адрес будет в формате `https://ВАШ-ЛОГИН.github.io/vibehunt-mvp/`.

Сайт использует только относительные пути `./`, поэтому одинаково работает в корне сайта и в подпапке репозитория. После публикации через HTTPS доступны функции копирования и отправки результата.

## Как тестировать локально

**Самый простой способ:** откройте двойным нажатием `preview_offline.html`. Это полный тест в одном файле, который работает даже без интернета.

Для проверки настоящей версии GitHub Pages требуется любой статический веб-сервер, потому что `index.html` использует JavaScript-модули.

```bash
python3 -m http.server 8000
```

Затем откройте `http://localhost:8000`.

Запуск проверок расчёта (нужен Node.js 18+):

```bash
node --test test.mjs
```

Пересобрать офлайн-превью после изменений в исходных файлах:

```bash
node build_preview.mjs
```

## Модель подсчёта

Рабочий стиль:

```
Индекс = 0.60 × (пары/4) + 0.25 × (качества/3) + 0.15 × ((интерес−1)/4)
```

Мотивация:

```
Индекс = 0.80 × (зелёные флаги/4) + 0.20 × (красные флаги/3)
```

Если разница двух сильнейших стилей меньше `0.08` или двух мотиваций меньше `0.10`, считаем результаты близкими. Это **гипотезы для пилота** — показатели валидности и надёжности теста ещё не установлены.

Тексты заданий, варианты ответов, описания 15 Вайбо: `content.mjs`.

Расчёт, проверка ответов и пороги различимости: `scoring.mjs`.

Экранные сценарии и таймер: `app.mjs`.

Внешний вид: `styles.css`.

## Приватность и ограничения MVP

- Всё тестирование выполняется в браузере. **Ответы не передаются на сервер** и не сохраняются в базе данных.
- Чтобы прогресс не терялся от обновления страницы, ответы и время окончания сохраняются в `sessionStorage` текущей вкладки.
- Отсчёт не ставится на паузу при закрытии/обновлении страницы: если вкладка восстановлена, дедлайн сохраняется.
- Отклик на результат тоже остаётся только в браузере; для аналитики пилота впоследствии потребуется отдельное сохранение с информированием пользователей.
- Подключение основного тестирования, аккаунтов, аналитики и HR-профиля — будущие этапы, не часть этого MVP.
- Цветные иллюстрации Вайбо — временные SVG-маскоты, их можно заменить утверждённым арт-паком без изменения логики баллов.
- Политика распределения Вайбо не предназначена для кадровых решений; пока это игровая гипотеза о рабочих предпочтениях.

## Кому и где показывать тест

Предназначено для сотрудников: игровое знакомство с собой, вовлечение и желание пройти дальнейшую диагностику. Результат — не заключение о профессиональной пригодности и не оценка компетентности.
